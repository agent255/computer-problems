1
What is the output of the following program?
public class Q1 {
    public static void main(String[] args) {
        int a = 5;
        int b = a++ + ++a + a++;
        System.out.println(a + " " + b);
    }
}
▶ Answer & Logic
Output 
8 19
Step-by-step evaluation of a++ + ++a + a++:

1. a++ → returns 5 (post-increment; a becomes 6)
2. ++a → increments first to 7, returns 7
3. a++ → returns 7 (post-increment; a becomes 8)

So b = 5 + 7 + 7 = 19. Final a = 8.

Common mistake: Students assume left-to-right "final" values of a, computing 5+7+8. The key rule: each operand is fully evaluated (including its side-effect on a) before the next operand is read.

public class Q2 {

        String s2 = new String("Hello");

        System.out.println(s1.equals(s2));

▶ Answer & Logic
Output 
false
true
0
Why == is false: s1 points to the String pool literal. new String("Hello") explicitly creates a new object on the heap. They are different references — different memory addresses — so == (reference equality) returns false.

Deadly trap: Many students write true for ==, forgetting that new String() bypasses the pool.

public class Q3 {

▶ Answer & Logic

100
Variable Shadowing: The parameter x in show(int x) shadows the class-level static field x. Inside show, the name x refers exclusively to the local parameter, not the static field.

public class Q28 {

            for (int j = 0; j < n - 1 - i; j++) {
                if (a[j] > a[j + 1]) {

▶ Answer & Logic
Pass-by-pass Trace 
Initial:  [9, 3, 7, 1, 5]

Pass 1 (i=0): j goes 0..3
  j=0: 9>3 → swap → [3, 9, 7, 1, 5]
  j=1: 9>7 → swap → [3, 7, 9, 1, 5]
  j=2: 9>1 → swap → [3, 7, 1, 9, 5]
  j=3: 9>5 → swap → [3, 7, 1, 5, 9]
End Pass 1: [3, 7, 1, 5, 9]  ← 9 bubbled to end

Pass 2 (i=1): j goes 0..2
  j=0: 3>7? No
  j=1: 7>1 → swap → [3, 1, 7, 5, 9]
  j=2: 7>5 → swap → [3, 1, 5, 7, 9]
End Pass 2: [3, 1, 5, 7, 9]

Pass 3 (i=2): j goes 0..1
  j=0: 3>1 → swap → [1, 3, 5, 7, 9]
  j=1: 3>5? No
End Pass 3: [1, 3, 5, 7, 9]

Pass 4 (i=3): j goes 0..0
  j=0: 1>3? No
End Pass 4: [1, 3, 5, 7, 9]
Output: 1 3 5 7 9

Inner loop bound: j < n-1-i ensures already-sorted elements at the right end are not compared again. This is the correct, optimized form.

public class Q30 {
    public static void main(String[] args) {
        int a = 17, b = 5;
        System.out.println(Math.pow(2, 3));
        System.out.println(a % b + Math.floor(a / b));
        System.out.println(Math.max(a % b, (int) Math.sqrt(a)));
        System.out.println((int) Math.round(2.5) + (int) Math.round(3.5));
        System.out.println(Math.abs(-7) + " " + Math.abs(-7.9));
    }
}
▶ Answer & Logic
Line-by-line justification 
Line 1: Math.pow(2,3) = 8.0   → Output: 8.0

Line 2: a%b = 17%5 = 2 (type int)
         a/b = 17/5 = 3  ← INTEGER DIVISION (both ints!)
         Math.floor(3) = 3.0
         2 + 3.0 = 5.0   ← int+double promotes to double
         Output: 5.0

Line 3: a%b = 2
         Math.sqrt(17) ≈ 4.123, (int)4.123 = 4
         Math.max(2, 4) = 4
         Output: 4

Line 4: Math.round(2.5) = 3  (rounds up — half-up rule)
         Math.round(3.5) = 4  (rounds up — half-up rule)
         (int)3 + (int)4 = 7
         Output: 7

Line 5: Math.abs(-7) = 7   (returns int)
         Math.abs(-7.9) = 7.9 (returns double)
         7 + " " → "7 " (string concat)
         "7 " + 7.9 → "7 7.9"
         Output: 7 7.9
Final Output: 
8.0
5.0
4
7
7 7.9
Multi-trap dissection:
• Line 2: The most dangerous trap — a/b is integer division first, then passed to Math.floor. Not 17.0/5 = 3.4.
• Line 4: Math.round uses "round half up" (banker's rounding is NOT used in Java). Both 2.5 and 3.5 round up.
• Line 5: Math.abs(-7) returns int 7; Math.abs(-7.9) returns double 7.9. The "7 " + 7.9 concatenation produces a string, not a sum.
